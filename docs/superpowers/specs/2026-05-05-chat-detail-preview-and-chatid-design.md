# Chat 详情页预览遮罩与 chat_id 语义修复设计

## 背景

当前会话详情页存在 4 类问题：

1. 文件最大化预览时，底层消息区域仍可能滚动，导致“预览层 + 消息层”同时变化，视觉混乱。
2. 在 `/chat/:id` 继续对话时，请求语义不稳定，`chat_id` 不是强约束为 URL 中的会话 id。
3. 详情接口存在性判断走了列表接口查找，逻辑不准确，且与详情页语义不一致。
4. 详情接口返回体缺少 `chat_id`（第三方会话 id），前后端字段语义不够清晰。

## 用户确认约束

1. 文件最大化预览行为：采用“全遮罩覆盖 + 底层不可滚动/不可交互”。
2. 继续对话时：前端请求中的 `chat_id` 必须强制使用 URL 的 `id`。
3. 详情接口新增字段：`chat_id` 值使用第三方返回的 `chat.chat_id`。
4. 详情存在性判断：`server/api/v1/agent/chats/[id].get.ts` 必须调用第三方详情接口 `/buildagent/v1/agent/chats/{id}`，不再通过列表接口判断。

## 方案选型

### 方案 A（采用）：最小侵入修复

- 在 `app/pages/chat/[id].vue` 修复预览层遮罩与发送参数约束。
- 在 `server/api/v1/agent/chats/[id].get.ts` 改为详情接口判存，并补 `chat_id` 字段。
- 保持 `server/api/v1/agent/chats.post.ts` 的网关职责不变（继续统一附带 `app_name`）。

采用原因：

- 命中当前问题，改动集中，回归成本低。
- 不引入额外抽象层，适合当前发布窗口快速落地。

## 详细设计

### 1. 前端页面行为（`app/pages/chat/[id].vue`）

#### 1.1 文件最大化预览遮罩

目标：`maximizedFile` 有值时，预览层成为唯一交互层，页面底层不可滚动、不可点击。

设计要点：

- 预览层采用全视口遮罩，覆盖聊天页全部可见区域。
- 打开预览时同时锁定页面根滚动容器与聊天消息滚动容器，确保无滚动穿透。
- 预览打开期间屏蔽底层 pointer/scroll 事件，底层区域不可点击、不可文本选中。
- 关闭预览（点击还原/Esc）后恢复滚动能力。
- 在关闭、组件卸载、路由切换 3 个时机，都必须执行同一清理函数，避免页面残留“无法滚动”状态。

#### 1.2 继续对话发送语义

目标：详情页继续对话时，`chat_id` 与 URL 强一致。

设计要点：

- 发送请求体时，`chat_id` 固定取 `String(route.params.id)`。
- 不依赖 SDK 传入 `chatId` 来决定是否带 `chat_id`。
- 结果中的 `resolvedChatId` 仅用于响应兜底和路由一致性检查，不反向覆盖发送侧 `chat_id`。
- 该强约束必须落在请求体构造处，并覆盖首次发送、重试、再生消息等发送路径。

#### 1.3 前端数据契约对齐

- 详情页数据模型（`ChatData`）需新增 `chat_id: string`。
- 页面内涉及路由语义时读取 `id`，涉及上游会话语义时读取 `chat_id`。
- 禁止把 `id` 与 `chat_id` 视为可互换字段。

### 2. 服务端详情接口（`server/api/v1/agent/chats/[id].get.ts`）

#### 2.1 存在性判断改造

目标：详情接口按详情语义判存，而非列表查找。

设计要点：

- 移除 `GET /buildagent/v1/agent/chats` 列表查询 + `find` 判存逻辑。
- 改为先调用第三方详情接口 `GET /buildagent/v1/agent/chats/{id}`。
- 详情接口返回 404 时，直接向前端返回 404 `Chat not found`。
- 若详情存在，再继续执行日志流读取与消息转换流程。
- 第三方详情接口参数语义按已确认约束处理：`{id}` 直接使用当前 URL 的会话 id。

#### 2.2 返回字段补充

在详情接口最终返回对象中新增：

- `chat_id: chat.chat_id`

保留现有字段：

- `id`
- `title`
- `createdAt`
- `messages`
- `lastTimestamp`
- `isOwner`

字段语义约定：

- `id`：固定等于请求路径参数 `:id`（当前路由 id）
- `chat_id`：第三方会话 id（用于上游会话语义）
- 任意实现不得用 `chat.chat_id` 回写 `id`，也不得用第三方其他主键替代路由 `id`。

### 3. 网关接口职责边界（`server/api/v1/agent/chats.post.ts`）

该文件维持现有约束：

- 始终给第三方带 `app_name: "BuildAgentPortal"`。
- 继续对话与新建对话的差异只体现在 `chat_id` 是否为空。

说明：

- 用户观察到“继续对话时第三方没有 `app_name`”属于链路语义错位风险，本次通过“前端 `chat_id` 强约束 + 服务端职责边界明确”一并消除。

## 数据流（修正后）

1. 进入 `/chat/:id`：
   - 前端请求 `/api/v1/agent/chats/:id`
   - 服务端先调第三方 `/buildagent/v1/agent/chats/:id` 判存
   - 存在则继续读取日志流生成 `messages`
   - 返回 `id + chat_id + messages + lastTimestamp...`

2. 在详情页发送新消息：
   - 前端 `POST /api/v1/agent/chats`，body 中 `chat_id = route.params.id`
   - 服务端网关转发第三方，统一附带 `app_name`
   - 返回 `chat_id` 后，继续使用同一个会话标识（`resolvedChatId`）拉取流式增量

3. 打开文件最大化预览：
   - 进入遮罩态，底层消息区不可滚动/不可交互
   - 关闭后恢复交互能力

## 错误处理

1. 第三方详情接口返回 404：
   - 直接抛 404，消息为 `Chat not found`。
2. 详情存在但日志流获取失败：
   - 维持现有错误语义，返回明确 5xx。
3. 前端发送前参数校验失败：
   - 若 `route.params.id` 不是非空字符串，则阻断发送并提示“请求参数异常”。
4. 预览遮罩清理失败：
   - 在关闭、卸载、路由切换 3 个时机都执行滚动锁清理兜底。

## 验收标准

### 交互验收

1. 打开最大化预览后，滚轮/触控板不会滚动到底层消息列表。
2. 预览打开期间，底层消息不可点击和文本选中。
3. 关闭预览后，消息区恢复正常滚动与交互。

### 协议验收

1. 在 `/chat/:id` 发送消息时，`POST /api/v1/agent/chats` 的 `chat_id` 恒等于 URL 中 `id`。
2. 转发到第三方时，始终包含 `app_name: "BuildAgentPortal"`。

### 接口验收

1. `GET /api/v1/agent/chats/:id` 不再依赖列表接口判存。
2. 响应结构包含 `chat_id`，且取值来自第三方详情数据 `chat.chat_id`，并满足非空。
3. 无效 id 访问详情时返回 404。

## 风险与回退策略

- 风险：第三方详情接口不可用时，详情页判存失败率上升。
- 观测：记录详情接口调用的 4xx/5xx 比例与耗时，便于快速定位异常。
- 回退：保留应急降级开关（仅用于故障处置），但默认路径始终是“详情接口判存”。

## 影响范围

- `app/pages/chat/[id].vue`
- `server/api/v1/agent/chats/[id].get.ts`
- （验证）`server/api/v1/agent/chats.post.ts`

## 不在本次范围

1. 会话 ID 体系全面重构（如统一 `id/chat_id` 为单字段模型）。
2. 聊天列表页的数据结构调整。
3. 文件预览组件功能扩展（仅处理详情页遮罩交互一致性）。
